# КАРАОКЕ МЕЧТЫ 2.0 — Техническое задание (ТЗ)

> Метафора проекта. Среда — тензорное поле: она не толкает вектор, а только
> объявляет цену каждого шага. Певец — вектор: `v(t+1) = v(t) + Δv`.
> Караоке не должно тащить голос за собой — оно должно выстраивать вокруг
> голоса среду, в которой каждый следующий шаг дешевле предыдущего.
> Эта уникальность — **сингулярное** — реализована как «Зелёный коридор».

## 1. Цель

Домашнее караоке на текстах RUVSON (папка `download/`, статус «ЧИСТОВИК»),
работающее как статическое веб-приложение без сервера и без передачи данных:
открыл — поил. Пять песен первого альбома зашиты в приложение; минусом служит
либо локальный файл пользователя, либо встроенный синтезатор.

## 2. Пять слоёв (канон продукта)

### Слой 1 — Контентный движок
- Пять эталонных текстов «ЧИСТОВИК» встроены в `karaoke/songs.js` (структура:
  секции `verse/chorus/bridge/outro/final`, строки — атомы карaoke).
- Источник минуса: пользовательский аудиофайл (mp3/wav/ogg/m4a/flac/opus,
  кнопка или drag&drop) **или** встроенный «Синт-минус» (Am–F–C–G, 96 BPM:
  пад, бас, клик, снейр — генерируется WebAudio, ничего не грузится).
- Оригиналы на YouTube указаны ссылкой в карточке песни (захват аудио
  из YouTube статическим приложением невозможен и недопустим).

### Слой 2 — Голосовой комфорт
- «Голос» → тест диапазона: три замера по 3 секунды (свободно / низко /
  высоко) → запоминаются опорные ноты (медиана детекций).
- Транспонирование ±12 полутонов: слайдер на Сцене; для файла — гранулярный
  питч-шифтер (AudioWorklet, темп сохраняется), для синth-минуса — прямое
  умножение частот.
- Подсказка после попытки: если медиана голоса ушла за комфортную зону,
  приложение предлагает сдвиг в полутонах.
- Гид-стрелки: если для песни есть эталон-контур, у строки стоит стрелка
  направления мелодии (↑ вниз ↓ вверх → держать).

### Слой 3 — Реальный фидбек
- Подсветка текущей строки с заливкой прогресса, следующие строки видны,
  пройденные гаснут; отсчёт «3-2-1» перед первой строкой.
- Счёт двух режимов: «Дружелюбный» (квадратичная кривая, щадящие пороги)
  и «Судья» (сырые числа, строгие пороги уверенности).
- Формула строки: `p` — доля вокализованных кадров, `s` — устойчивость
  (`1 − медианное отклонение/норма`), `r` — близость к эталон-контуру
  (октавно-свёрнутая дельта медиан). Веса:
  - дружелюбный: `0.55p + 0.30s + 0.15r` (без эталона `0.62p + 0.38s`),
    финал `100·√(raw/100)`;
  - судья: `0.45p + 0.35s + 0.20r` (без эталона `0.56p + 0.44s`), финал raw.
- Эталон-контур: первая полная попытка (покрытие ≥ 50 % строк) записывает
  медиану и направление каждой строки; следующие попытки оцениваются
  относительно неё с поправкой на разницу транспозиций.
- Кривая питча: скользящее полотно последних 6 секунд на канвасе.
- Лучшие результаты хранятся по песне и режиму.

### Слой 4 — Пати
- Очередь певцов с цветами, бейдж «сейчас поёт», ротация по числу попыток.
- Турнирная таблица вечера: певец, песня, режим, счёт; в зачёт идут только
  полные попытки (покрытие ≥ 60 % строк). Сброс вечера — с подтверждением.

### Слой 5 — Атмосфера
- Неоновая тёмная тема (маджента/циан/зелёный), сетка-космос, свечение
  только на действующих элементах.
- Большой экран (крупные строки) и полноэкранный режим.
- Неон-пад между песнями: медленный генеративный аккордовый дрейф,
  автоматически умолкает, когда начинается трек.

## 3. Сингулярное — «Зелёный коридор»

Песня начинается в комфортной тональности (слайдер или подсказка Голоса).
Если попытка дотянула до порога (дружелюбный ≥ 75, судья ≥ 65), коридор
сам сужается на один полутон в сторону оригинала. Среда адаптируется к
вектору, а не вектор к среде. Состояние коридора хранится отдельно от
ручного слайдера и отображается зелёной полосой «до оригинала». Сброс —
кнопкой. Ручной слайдер и коридор независимы: коридор лишь предлагает
новое значение после удачной попытки.

## 4. Синхронизация (мастер меток)

- Экран «Синхро»: список строк, транспорт, большая кнопка ТАП и Пробел.
- Метка ставится в текущую строку в момент нажатия, курсор идёт дальше;
  отмена метки, −3 сек, клик по строке — переход к ней.
- Сохранение в localStorage по id песни (привязка к песне, не к источнику).
- Экспорт/импорт **LRC**: метаданные `ti/ar/al`, кастомный тег `label`
  для названий секций; импорт отклоняется при несовпадении числа строк —
  тексты каноничны, «примерно» не принимается.

## 5. Модель данных (localStorage, префикс `km2:`)

| Ключ | Содержимое |
|---|---|
| `timings:<songId>` | `{ starts: [sec|null], audioName? }` |
| `best:<songId>:<mode>` | лучший счёт (число) |
| `ref:<songId>` | `{ offset, coverage, lines: [{m, dir}|null] }` |
| `corridor:<songId>` | `{ offset }` — текущий сдвиг коридора |
| `voice` | `{ free, low, high, ts }` (ноты MIDI) |
| `party` | `{ singers: [{name,color}], active, results: [...] }` |
| `mode` | активный режим счёта |

## 6. Технические решения

- **Детектор высоты**: нормированная автокорреляция с параболической
  интерполяцией (окно 2048, порог RMS, диапазон 65–1200 Гц), кадры ~60 Гц.
- **Питч-шифтер**: AudioWorklet, схема «пила на линии задержки» — две линии
  с дрейфом задержки `k = 1 − 2^(st/12)`, окна Ханна со сдвигом ползерна,
  зерно 2200 сэмплов; при `st = 0` — прозрачный байпас. Fallback: если
  AudioWorklet недоступен, транспонирование файла отключается с уведомлением,
  остальное работает.
- **Микрофон**: AnalyserNode без вывода на выход (защита от заводки),
  обрабатывается только в пределах вкладки. Никакой сети.
- **Безопасность контекста**: getUserMedia требует https или localhost;
  при запуске с `file://` приложение честно сообщает об этом. Рабочий запуск:
  `python3 -m http.server` из корня репозитория → `http://localhost:8000/karaoke/`.
- **Хранение**: только localStorage; экспорт — файлы LRC.

## 7. Ограничения прототипа (честные)

1. Питч-шифтер гранулярный: на полифоническом материале допустим лёгкий
   «хорус» — для караоке приемлемо; продакшн-путь — прекомпилированные
   минуса нужных тональностей (см. роадмап).
2. Эталон-контур — медианы, а не посимвольная мелодия; гид-стрелки грубые.
3. Счёт не знает истинной мелодии песни, пока не записан эталон: первые
   попытки оцениваются по присутствию и устойчивости.
4. Пати — локальный (одна вкладка). Мультидевайс требует сервера — роадмап.
5. `file://` не даёт микрофона; нужен localhost/https.

## 8. Критерии приёмки MVP

- Открытие без сборки и сервера (кроме микрофона) — да.
- Пять песен с полными текстами ЧИСТОВИК — да.
- Синхронизация тапом, сохранение, экспорт/импорт LRC — да.
- Подсветка, отсчёт, заливка строки — да.
- Транспонирование файла и синth-минуса в ±12 пт — да.
- Счёт в двух режимах, эталон-контур, гид-стрелки — да.
- Зелёный коридор с автосужением — да.
- Пати-очередь и зал славы — да.
- Ни один байт не покидает вкладку — да.
