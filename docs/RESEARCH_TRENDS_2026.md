# Разведка трендов и рабочих практик (октябрь 2026) → апгрейд v3.0

Принцип: среда = тензорное поле лучших практик мира; вектор = продукт.
Ниже — что нашла сеть, что из этого рабочее, и куда это легло в код.

## Найдено и применено

### 1. Счёт по строкам + октавная эквивалентность + «что тренировать»
Источник: Autunes, «How Karaoke Scoring Actually Works» (окт 2026) —
autunes.com/blog/how-karaoke-scoring-works. Практики: пич измеряется много
раз в секунду; сравнение с мелодией с допуском по времени; **октава вверх/вниз
и смена тональности не штрафуются, штрафуется дрейф**; счёт строится
по строкам, слабые строки показываются с реплеем.
У нас уже было: построчный счёт, octFold, поправка на транспозицию.
Добавлено в v3.0: панель «Что тренировать» — 3 слабейшие строки (<60)
с кнопкой перехода к строке (seek −0.8 с и пуск).
Также сверено с USKA (uskakaraoke.com/about/scoring-system): питч-точность +
ритм/тайминг — наши факторы p/s/r соответствуют.

### 2. Нотные трубки (note tubes)
Источники: UltraStar-Deluxe (формат и игра, спека USDX 1.1.0/1.2.0 —
github.com/UltraStar-Deluxe/Play#503, UltraStar-Manager#61), Performous,
запрос сообщества «karaoke that shows pitch along with lyrics»
(reddit.com/r/karaoke/1c3xh7r). Стандарт визуального фидбека караоке-игр —
трасса ноты, по которой идёт живой голос.
Добавлено в v3.0: эталон строки хранит **траекторию** (24 ведра медиан,
относительные полутоны, октавная свёртка, заполнение дыр соседями) —
канвас #tube-canvas рисует трубку эталона и белые точки живого голоса
в окне строки. До первой полной попытки — пунктирная ось и голос по
скользящей медиане.

### 3. Запись дубля + экспорт
Источник: Karaoke Sync (App Store, 2026) — «Import a song, paste the lyrics,
tap along to time each line. Then sing, record, or export». Паттерн
«вставь → тапай → пой → записывай → экспортируй» подтверждён рынком.
Добавлено в v3.0: MediaRecorder пишет **микс минус+голос** (MediaStream-шина
mixDest, без выхода на колонки — нет заводки), дубли в IndexedDB
(база `km2`, стор `takes`), панель «Дубли»: слушать / скачать / удалить.
Родной гид-вокал из концепта: кнопка «Гид» назначает дубль подсказчиком —
он тихо (0.22) подыгрывает с подстройкой позиции к транспорту.

### 4. Дуэты и распределение строк + живой питч-шифт
Источник: блог Smule (июль 2025) — «Testing Phase: Pitch-Shifting for Duets
& Groups» (sing.salon/forums/topic/3821): питч-шифтинг стал штатной функцией
массового караоке; дуэты — ядро продукта Smule (App Store: «Sing, Duet &…»).
Наш гранулярный шифтер (v2) совпал с трендом. Добавлено в v3.0:
режим «Дуэт» — секции чередуются между певцами (куплеты — соло, припевы —
хором), строки получают цвет и бейдж певца, в зал славы пишутся
под-счёты по певцам (parts).

### 5. Детекция тональности (Krumhansl-Schmuckler)
Источники: gist bmcfee (github.com/bmcfee — KS-оценка по распределению
pitch-классов), CCRMA ICMC-01 (Krumhansl-Schmuckler: суммирование питч-классов
→ сравнение с профилями), тренд «бесплатный аналог Mixed In Key»
(reddit.com/r/audioengineering/1s769x2).
Добавлено в v3.0: chroma через собственный radix-2 FFT (8192, хоп 4096,
Ханн, 55–2093 Гц) → корреляция с 24 профилями KS → «Тональность файла:
F♯ minor» прямо на Сцене. Второй клик по чипу — «Старт по голосу»:
тоника, ближайшая к комфортному центру голоса, задаёт стартовое смещение
коридора. Анализ порциями с setTimeout, чтобы не морозить UI; >60 МБ — пропуск.

### 6. Свои песни через вставку текста
Источник: тот же Karaoke Sync + блог Smule про загрузку своих песен
(blog.smule.com/uploadsongsmule — «tap along to time each line»).
Добавлено в v3.0: «Добавить свою песню» в Библиотеке: вставка текста,
парсер секций по заголовкам с двоеточием («Куплет 1:», «Припев:», любые
свои: «Проигрыш:»), тип секции угадывается (verse/chorus/bridge/outro/final),
песня живёт в localStorage, вся механика (синхро, счёт, коридор, дубли)
подхватывается автоматически; удаление чистит все ключи.

### 7. Разогрев голоса
Источник: практики вокальных тренажёров (категория AI singing apps,
vibesing.me/blog/ai-singing-app-guide-2025): разминка перед пением —
стандарт заботы о голосе.
Добавлено в v3.0: «Разогрев 60 сек» — сценарий с подсказками и WebAudio-
глиссандо (сирены, пять нот вверх/вниз), живая нота на экране, дата
последнего разогрева сохраняется.

### 8. Платформенный канон: MediaSession + PWA
Источники: Media Session API (developer.chrome.com, Chromium README) —
метаданные и управление с локскрина; PWA-практики 2025 (installable,
offline-first service worker).
Добавлено в v3.0: manifest.webmanifest + icon.svg (неоновый КМ2) + sw.js
(cache-first с сетевым обновлением, версия km2-v3.0); MediaSession:
название/исполнитель/альбом, кнопки play/pause/±3 сек, позиция для локскрина.

## Найдено и осознанно отложено (с причинами)

### Разделение стемов в браузере (Demucs ONNX Runtime Web)
Источники: incidentist/web-audio-separation («runs entirely in the browser
with ONNX Runtime Web»), Podter/demucs-web (self-hosted, нужен GPU),
htdemucs-core-onnx (HuggingFace, июнь 2026: STFT вынесен наружу).
Вывод: работает, но модель ~80 МБ и хочется WebGPU — для домашнего MVP
избыточно. Общая практика рынка подтверждена: AI-сепарация — штатный
инструмент карaoke (mixingandmastering.ai: «Karaoke and live backing tracks»
— легитимный кейс;vocals ~92 % качества). Путь: этап 2 роадмапа — прекомпилированные
минуса и стемы на стороне автора песен; в-браузерная сепарация — этап 3+.

### Word-level тайминги (UltraStar/AMLL)
Формат USDX 1.2.0 живёт, но поэлементный тап утяжеляет синхронизацию в 5–7 раз.
Построчный тап + заливка строки покрывают домашний кейс. Отложено: экспорт
UltraStar .txt (этап 1) — после стабильности построчных меток.

### Социальный хостинг шоу (OpenKJ 2.1.39, авг 2025)
Karaoke-show-хостинг — отдельный класс ПО. Наш «Пати» остаётся локальным;
мультидевайс — этап 3 (WebRTC/WS).
